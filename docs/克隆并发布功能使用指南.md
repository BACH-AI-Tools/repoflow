# 🚀 克隆并发布功能使用指南

## 功能概述

这个功能允许你：
1. **克隆**别人的GitHub仓库
2. **自动修改包名**（添加`bachai`前缀，避免包名冲突）
3. **上传到你的组织**GitHub仓库
4. **自动触发CI/CD**，立即打包发布到包源（PyPI/NPM）
5. **发布到EMCP平台**

## 使用方法

### 方式一：GUI界面（推荐）

1. **启动GUI**
   ```bash
   python repoflow_ultimate.py
   ```

2. **切换到"克隆仓库"标签页**
   - 在界面顶部点击 `🔗 克隆仓库` 标签

3. **填写信息**
   - **GitHub 仓库URL**: 输入要克隆的仓库地址
     - 例如：`https://github.com/username/awesome-mcp`
   - **包名前缀**: 默认为 `bachai`，会自动添加到包名前面
     - 原包名：`awesome-mcp` → 新包名：`bachai-awesome-mcp`
   - **目标组织**: 你的GitHub组织名称（例如：`BACH-AI-Tools`）

4. **点击"克隆并发布"按钮**

5. **等待完成**
   - 会显示实时进度和日志
   - 整个过程约3-5分钟（取决于仓库大小和网络速度）

### 方式二：命令行

```bash
# 基本用法
python clone_and_publish.py https://github.com/user/awesome-mcp

# 自定义前缀
python clone_and_publish.py https://github.com/user/awesome-mcp --prefix myprefix

# 指定输出目录
python clone_and_publish.py https://github.com/user/awesome-mcp --output ./repos

# 完整示例
python clone_and_publish.py \
    https://github.com/user/awesome-mcp \
    --prefix bachai \
    --output ./my_repos
```

## 包名规则

### Python项目
- **原包名**: `my-package`
- **新包名**: `bachai-my-package`
- **安装命令**: `uvx --from bachai-my-package@1.0.0 bachai_my_package`

### Node.js项目
- **原包名**: `my-package`
- **新包名**: `bachai-my-package`
- **安装命令**: `npx bachai-my-package`

### 带Scope的NPM包
- **原包名**: `@org/my-package`
- **新包名**: `@org/bachai-my-package`（保留scope）

## 许可证与署名（必读）

重新发布别人的开源项目，必须保留原作者署名和许可证。工具会自动做这些：

- **上游没有许可证文件就停止**：没有许可证 = 没有授权，不能重新发布。如果已经取得原作者的书面许可，用 `--allow-unlicensed` 继续，这个确认会写进 `UPSTREAM.md`。
- **上游的 `LICENSE` / `NOTICE` 原样保留**，不改、不删。
- **生成 `UPSTREAM.md`**：上游地址、克隆时的提交号、原作者、许可证，以及许可证带来的额外义务（例如 Apache-2.0 要保留 NOTICE，GPL 类要求衍生作品同样开源）。
- **自动生成的 `setup.py` / `pyproject.toml` / `package.json` 用上游的作者和许可证**，不会写成 BACH Studio / MIT；`pyproject.toml` 的 `[project.urls]` 带上 `Upstream`。
- **GitHub 仓库描述**写成 `<新包名> - based on <上游地址> (<许可证>)`；发布到模板目录时作者是原作者。

发布前请人工看一眼 `UPSTREAM.md` 里的警告。识别不出许可证类型时，工具会提示人工确认。

## 注意事项

0. **许可证与署名**
   - 见上一节；上游没有许可证时默认不会发布
   - GPL / AGPL 等 copyleft 许可证的项目，重新发布时同样必须以该许可证开源

1. **GitHub Token权限**
   - 需要有创建仓库的权限
   - 需要有设置Secrets的权限
   - 需要有推送代码的权限

2. **包源Token**
   - Python项目需要PyPI Token
   - Node.js项目需要NPM Token
   - Token会自动设置到GitHub Secrets中

3. **包名冲突**
   - 前缀功能可避免与原包名冲突
   - 建议使用有意义的前缀（如公司/团队名）

4. **首次发布**
   - 克隆后会立即创建Tag触发发布
   - GitHub Actions通常需要2-3分钟完成打包
   - 工具会自动等待包发布成功

5. **临时目录**
   - 克隆的仓库默认保存在临时目录
   - 可以通过 `--output` 参数指定保存位置
   - 完成后可手动清理临时目录

## 故障排查

### 问题1：克隆失败
- **检查**: 源仓库URL是否正确
- **检查**: 网络连接是否正常
- **检查**: 是否有权限访问该仓库

### 问题2：包名修改失败
- **原因**: 项目结构不符合标准
- **解决**: 确保项目有 `pyproject.toml`、`setup.py` 或 `package.json`

### 问题3：GitHub推送失败
- **检查**: GitHub Token是否有效
- **检查**: 组织名称是否正确
- **检查**: 是否有推送权限

### 问题4：包发布失败
- **检查**: GitHub Actions日志
- **检查**: PyPI/NPM Token是否有效
- **检查**: 包名是否已存在（应该不会，因为有前缀）

### 问题5：EMCP发布失败
- **检查**: EMCP账号配置是否正确
- **检查**: 验证码是否正确
- **检查**: 网络连接是否正常

## 技术细节

### 包名修改原理

**Python项目**:
```python
# 原 pyproject.toml
[project]
name = "awesome-mcp"

# 修改后
[project]
name = "bachai-awesome-mcp"
```

**Node.js项目**:
```json
// 原 package.json
{
  "name": "awesome-mcp"
}

// 修改后
{
  "name": "bachai-awesome-mcp"
}
```

### GitHub Actions自动触发

创建Tag时会自动触发对应的发布工作流：
- Python: `.github/workflows/pypi-publish.yml`
- Node.js: `.github/workflows/npm-publish.yml`

工作流会自动：
1. 构建包
2. 运行测试
3. 发布到包源
